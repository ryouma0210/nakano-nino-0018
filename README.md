# Nino Room

会話形式で各部屋のイベントを進め、チェック、調教、お仕置き、射精管理、ポイント、ご褒美などを端末内へ記録するスマートフォン向けローカルアプリです。

アプリ本体は `habit-diary-timer-mobile/` にあります。

## 現在の構成

| 項目 | 内容 |
|---|---|
| アプリ名 | Nino Room |
| アプリバージョン（スマホ・WEB・Windows共通） | 1.1.1 |
| パッケージID | `jp.local.habitdiarytimer` |
| Framework | Expo SDK 57 / React Native 0.86 |
| Language | TypeScript |
| 画面向き | 縦画面固定 |
| データ保存 | SQLite、AsyncStorage、アプリ専用ファイル領域 |
| 通信 | 通常利用では不要 |
| Android配布 | Release APK |
| iOS配布 | EAS / TestFlight設定のみ。現時点では実機配布未検証 |

## 主な特徴

- 二ノとのタップ式会話
- 設定した名前を使った呼びかけ
- 契約成立後だけ表示される赤文字の専用会話
- 日付単位の敗北・準備チェック
- 本日の命令、射精管理、調教、お仕置きの自動記録
- 調教・お仕置き用に分けた画像／動画の端末内格納
- リズムゲージ、効果音、ループ音声
- ポイント獲得、ご褒美交換、コレクション
- 二ノ様の控室での画像／動画表示、着せ替え
- 館の外へ出る軽量RPG風ミニゲーム
- ゲーム部屋のすごろく：マスごとの移動ルール、途中再開、プレイ履歴
- マイページでの名前変更、ステータス設定、弱点診断
- 起動時ログインボーナス確認、本日の記録、週間報告、記録カレンダー
- タスク画面で所持Pt、本日の獲得Pt、今日の達成状況、実施済・未完了項目を確認し、対象画面へ移動
- 称号・実績
- オフライン動作
- 「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターで主要画面へ移動
- 格納ファイルの複数選択、保存進捗・成功件数・失敗ファイルの表示

各調教系の部屋には「部屋から出る」と「ホームへ戻る」を配置します。ゲーム部屋から廊下へ移動するボタンも「部屋から出る」と表示します。記録・交換系の画面には「記録・交換メニューへ戻る」、管理・設定系の画面には「管理・設定メニューへ戻る」を配置します。

開始後の画面には「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターを表示します。「タスク」で本日の状況を確認できます。「記録」は記録・交換メニュー、「設定」は管理・設定メニューへの入口です。開始画面、館の外、全画面モーダルには表示せず、スマートフォンでの文字入力中は隠します。

Windows・WEBの広い画面では、同じ8項目を左側のナビゲーションに表示します。会話・画像と操作欄を左右に配置し、タスクは2列表示になります。ウィンドウを狭くすると縦並びへ戻ります。「アプリ設定」の「画面表示」で全画面表示を切り替えられ、Windows版では表示倍率も変更できます。Windows版の全画面状態と表示倍率は次回起動時にも引き継ぎます。

WEB・Windows版の控え室は、画像・動画の全体がウィンドウ内に収まるように表示します。調教・お仕置きのリズムゲージは中央配置・最大幅430pxとし、大画面でもマーカーの移動距離が伸びすぎないようにしています。リズムの周期・効果音・タイマーは画面サイズで変更しません。

## タスクの本日の状況

対象項目の表示順は「ログインボーナス→敗北部屋→洗脳部屋→準備部屋→本日の命令→調教部屋→射精管理部屋→お仕置き部屋→館の外」です。未契約・対象外・管理期間外の項目は同じ優先順のまま一覧の末尾へまとめます。実施済になっても表示順は変えません。

タスク画面に所持Pt、本日の獲得Pt、今日の達成数と全項目を表示します。完了した項目も一覧に残し、緑色の「実施済」で表示します。条件の対象外の項目は非表示にせず、薄い表示と「対象外」「未契約」「管理期間外」の状態を付け、押すと対象画面へ移動できます。対象外の項目は達成数の分子・分母に含めません。常時の集計対象はログインボーナス、本日の命令、準備部屋、洗脳部屋、調教部屋、館の外です。館の外は「スライム倒し X/100pt」で当日の獲得状況を表示し、100ptで実施済になります。押すと館の外へ移動でき、翌日は0pt表示に戻ります。お仕置き部屋は当日最新の調教結果が目標時間未達の場合だけ集計対象となり、その結果の保存以降に正常終了すると達成になります。再び目標未達になれば未完了に戻り、最新の結果が目標達成なら対象外になります。新しい調教記録には判定タグを保存し、以前の記録は既知の難易度と実施秒数から判定します。判定できない記録は集計対象外になります。

敗北部屋は契約中だけ、管理の指示は今日が管理期間内の場合だけ集計対象になります。タスクの敗北部屋の項目は、未契約なら「未契約」と表示して契約部屋へ直接移動します。契約済みなら敗北部屋へ移動し、完了前は「未完了」、完了後は「実施済」と表示します。管理には開始日・終了日を含めた「現在の日数／総日数 日目」と今日の完了状態を表示し、その日の指示を完了した後も日数表示を残します。管理の最終日を完了して期間が終了しても、その日の達成数には残ります。館の外のクエストはこの集計に含めません。

本日の獲得Ptは当日のプラスのポイント取引だけを合計し、消費・吸収による減少やSTG固定加算は含めません。お仕置きの新しい途中終了記録は達成に含めません。以前の履歴は正常終了と途中終了を同じ完了区分で保存していたため、過去分は保存済みの区分に従います。

各項目は実施済でも押すと対象画面へ移動します。タスク画面へ戻った時、タスク画面を開いたままアプリが前面へ復帰した時、日付が変わった時に保存済みのデータを読み直します。状況表示だけで報酬を付与したり、日記や管理指示を作成したりはしません。

## 二ノ様の控室

二ノ様の控室は、通常の部屋一覧とは別の専用画面です。スマートフォンのキャラクターゲームのように、画面中央へ二ノを大きく表示し、下部にセリフ、横に操作ボタンを配置します。

現在の機能:

- 画像／動画表示
- セリフ切り替え
- 横ボタンから画像／動画、衣装、戻るを操作
- 衣装変更
- 交換衣装の300pt交換

通常衣装では共通の控室メッセージと通常衣装メッセージを表示します。通常衣装以外では、選択中の衣装ごとのメッセージだけを表示します。

## 館の外へ

館の外へは、二ノ様の控室の下にある軽量RPG風ミニゲームです。
入室時と再表示時は必ず中央の十字路から開始し、上へ進んだ場合のみ誘惑の森を表示します。

現在の機能:

- ヘッダなしで、マップエリアを画面上部に大きく表示
- 下部に「自分のステータス」と「操作」を分けて表示
- 下部パネルはスマホのナビゲーションバーに被りにくいよう、コンパクトに表示
- WEB・Windows版は十字キーとステータスボタンを大きく表示
- WEB・Windows版はキーボードの矢印キーでも移動可能（長押し対応）。看板・クリスタル・ステータスの表示中、エリア移動中、戦闘・会話イベント中は移動を停止
- WEB・Windows版は「タップ / Enter ▼」のメッセージをEnterキーでも進められます。長押しによる連続送りは行わず、選択肢やモーダルの操作はフォーカス中のボタンを優先します
- 自分のステータスには、Lv、HP、MP、本日獲得pt、魅了状態を表示
- マップを移動した場合は、移動元に合わせて端から開始します（右から戻ったら右端、上から戻ったら上側など）
- 説明文や結果メッセージはマップ内の最下部に表示し、タップすると閉じます
- 下方向またはドア操作でホーム画面へ戻る
- 中央の十字路には設定ポイントがあり、触れるとモーダルで主人公Lv、サキュバスLv、魅了を調整できます
- サキュバスLvは主人公Lvとは別に保存され、設定ではLv.1〜100の範囲で調整できます
- 主人公だけ上限Lv.120です。翌日の+10、スライム討伐の+1、戦闘勝利の+20、設定での調整・保存・再読込は120まで対応し、二乃様を含む敵の上限は100を維持します。HP・MP・各ゲージの上限は100のままです。
- 設定ポイントのクリスタルは、立ったまま横方向に回転しているように表示します
- 右の草原では背景に固定されたスライムではなく、4体のスライムがマップ上を自由に移動します
- 移動中のスライムへ主人公が接触すると討伐して消えます
- スライム討伐は1回10pt、1日100ptまで獲得できます
- 左の浄化エリアへ入ると、HP／MPを自動で全回復し、魅了も解除します。回復メッセージは緑色で表示します
- 上の誘惑の森では、影に隠れたサキュバスへ近づくと「！」が表示され、戦闘開始イベントへ移行します
- 戦闘画面は画像をメインに表示し、画像まわりの白枠は出さず、画像内の上にサキュバスLv／HPを表示します
- 画像上には「コメント」または「選択肢＋主人公HP／MP／魅了状態」のどちらかだけを表示し、コメントをタップすると選択肢へ切り替わります
- コメントは右下に「タップ ▼」を表示し、次に進める場所を分かりやすくしています
- 戦闘コマンドは「戦う」「降参する」「逃げる」の階層式です
- 「戦う」では「攻撃」「防御」を選択できます。防御すると誘惑ダメージを半減し、MPを少し回復します
- 「降参する」では「おっぱい」「お尻」「足裏」の負けイベントを選択できます
- 「逃げる」「攻撃」「防御／攻撃回避」には、それぞれ別の外RPG用効果音が鳴ります
- 魅了状態では逃げることができず、攻撃しても相手に当たりません。左の浄化エリアへ移動すると解除されます
- 攻撃するとサキュバスHPを削り、その後サキュバスが通常攻撃または誘惑攻撃で反撃します。通常攻撃時は尻尾イラストを表示します
- サキュバスの誘惑攻撃時は、耳舐め音声または乳首責め音声をランダムに再生します
- 耳舐め誘惑ではキスマーク画像を表示して魅了状態になり、乳首責め誘惑ではハート画像を表示します
- 誘惑攻撃ダメージは、初級10、中級20、女王50
- HPが0になる、または負けイベントを選ぶと、01画像で5セリフ、02画像で10セリフ、03画像で5セリフの誘惑イベントに入り、画像とコメントをタップ送りで切り替えます
- 誘惑イベント中は画像を大きく表示し、HP／MP／サキュバスHPバーは表示しません
- 負けイベント中は誘惑BGMへ切り替わり、02画像からループ音、03画像から射精音を再生します
- ゲームオーバー時は射精1回扱いで、主人公Lv、MP100、Pt50を吸収されます
- 主人公はLv.1／HP1／MP1になり、吸収されたLvはサキュバス側へ加算されます（最大Lv.100）
- ゲームオーバー時の結果には、吸収後のサキュバスLvも表示します
- バトル中は戦闘BGM、魅了状態では専用BGMへ切り替わります

## 調教・お仕置きメディア

調教用ファイルとお仕置き用ファイルは別フォルダで管理します。

| デフォルト動画 | 3回再生後、次の動画へ |

## すごろく

「進行ログを見る」から、出目と補正後の値、移動前後のマス、強制停止、マスのルールによる移動、効果の付与・解除を最新100件まで新しい順で確認できます。操作番号は100件を超えても継続します。ログは途中保存と終了履歴に含まれ、プレイ履歴の各ゲームからも開けます。旧セーブに含まれない過去の操作は補わず、更新後の次の操作から記録します。

「部屋 → ゲーム部屋 → すごろく」から遊べます。各マスのイベント表記と設定済みの画像を表示します。「命令完了」でそのマスの移動・効果を適用し、移動先にもイベントがあれば、完了後にサイコロを振れます。イベント完了後にマスのルールで移動した場合は、移動先のお知らせを約3秒間表示します。お知らせの表示中も操作できます。画像の下のカードに現在のマス名、残りマス数、コース名を1行にまとめ、強制停止マスでは同じ行に赤色で「強制ストップ」と表示します。その下の操作は左列に「命令完了」「リタイア」「失敗」、右列に「サイコロを振る」「タイマー」を配置します。サイコロのイラストは振っている間のポップアップだけに表示し、通常の画面には出目・補正後の出目・マスのルールを文字で表示します。ゴール達成時は残りマス数を表示しません。遊び方には指定された「■すごろくルール」「■あると便利道具」「■マスの色について」の3項目を、元の改行・番号・記号を保って表示します。

「遊び方を見る」の直上にある「マップを確認」から専用モーダルを開き、開始時と同じ `Map1.jpg`・`Map2.jpg` を確認できます。左右へのスワイプまたは前後のボタンで切り替え、「閉じる」でゲームへ戻ります。

「サイコロを振る」を押すとポップアップが開き、約0.9秒間、回転しながら跳ねる演出の後に補正前の出目を表示します。移動の補正がある場合は、その出目を一度保持してルール適用を知らせ、再びサイコロを動かしてから補正後の目を表示し、結果を保存します。保存後はポップアップを自動で閉じ、出目の結果だけを文字で残します。補正前の値も「元の出目」として残します。移動マス数の代わりに、次のロールへ適用する効果を「デバフ付与中」とともに「強制1マス移動」「出た目 −3」「出た目 −2」で表示します。1マス固定の効果がある場合は減算より優先し、そのルールだけを表示します。ペナルティのサイコロには移動の補正を表示しません。

| マス・条件 | 移動・効果 |
|---|---|
| 通常 | 出目の数だけ進む |
| 1・8・15 | 完了後に -6 へ移動 |
| 2・6・13・26 | 完了後にスタートへ移動 |
| 12 / 20 / 37 | 完了後に 9 / 16 / 29 へ移動 |
| 7・14・21・25 | 通過時も強制停止。余った出目は破棄 |
| -6〜-1 | 出目に関係なく1マスずつ進む |
| -1 | 通常モードでは、命令完了で持続する「出た目−2」を付与。スタートへ戻った後も毎回適用し、0移動や7・14の強制ストップでは消えない。再訪時にも付与 |
| 21 | 通常モードで命令完了後、「出た目−2」を解除し、25の分岐まで強制1マス移動に置き換える |
| 25 | 初回完了後、ゴール①か延長を選択。延長は取り消せず、再訪しても分岐しない |
| 延長コース | 出目から3を引く。スタートへ戻っても延長状態を維持 |
| 補正結果が0以下 | その場にとどまり、イベントを再実行せずサイコロを振り直す |
| ストップ1〜4 | 28と29、31と32、34と35、37と38の間に配置。通過時も強制停止 |
| ストップ4 | 命令完了後、それまでのデバフを置き換えてゲーム終了まで強制1マス移動 |
| 40の先 | ゴール② |

マイナスゾーンと1マス固定効果は出目補正より優先します。延長中の「−3」と、-1で付く「−2」は加算せず、延長の「−3」を使います。持続する「−2」は保存・再開後も維持します。旧仕様ですでに0へ消費された効果は訪問履歴が残っていないため推測で復元せず、次の-1の命令完了で再付与します。短いコースの残りマス数は25まで、延長時は挿入されたストップとゴール②を含む残りの位置数で計算します。

「リタイア」は専用イベントの完了後、「失敗」は直接、ペナルティ用のサイコロへ進みます。退出時点の残りマス数を固定し、`残りマス数 × 出目 × 10` の計算結果を単位なしで記録します。ゴール・ペナルティの「結果を記録して終了」でプレイ履歴に保存します。終了結果とプレイ履歴は、達成時に緑色で「ゴール①をクリア」または「ゴール②をクリア」と表示し、残りマスとペナルティは表示しません。未達成時は「未達成」、敗北コース（通常モード／ハードモード）、敗北マス、残りマス、ペナルティをこの順番で赤色表示します。敗北マスはリタイア・失敗を選んだ時点のマス名で、既存の保存済み位置から取得するため過去の履歴にも表示します。

進行は操作ごとに自動保存し、画面を離れたりアプリを再起動したりしても再開できます。終了履歴は各行の先頭に終了日（年月日）を表示し、最新100件を保持します。「プレイ履歴を表示する」ボタンから専用モーダルで新しい順に確認できます。通常画面には履歴の一覧を表示せず、履歴がない場合はモーダル内にその旨を表示します。履歴の「閉じる」ボタンはスクロール領域の外に固定しています。保存キーは `nino-room:sugoroku:v1`。既存のバックアップ・復元対象に含まれ、全データ初期化または「各部屋の記録」の部分初期化で消去します。

各マスの命令文は `src/features/sugoroku/instructions.ts` で管理し、画像の下のマス情報と一緒に表示します。日本語・英語・韓国語・中国語の言語設定に対応しています。右列の「サイコロを振る」の直下に「タイマー」ボタンを配置し、押すと残り時間・分設定・開始・リセットを操作するポップアップが開きます。時間設定は1〜999分の整数だけで、秒の入力欄はありません。「開始」ボタンは実行中に「一時停止」、一時停止中に「再開」へ切り替わります。開始後はボタンに「タイマー 00:00」の形式で残り時間を表示し、一時停止中もその時間を保ちます。開始前・リセット後・終了後はボタンの時間を表示しません。ポップアップを閉じても計測は続き、残り時間が0になると通知します。別の画面へ移動すると停止し、画面を開き直すと初期値に戻ります。アプリが背景にある間は経過時間を数え、復帰時に表示と通知を更新します。タイマーはアプリ再起動後には引き継ぎません。

「遊び方を見る」はゲーム開始前も閉じた状態です。開くと先頭にマップ①が通常モード、マップ②がハードモードであることと、ハードモードは25マスに到達した人だけが選択できる説明を表示します。

### 各マスへの画像の設定

画像の配置先は [`habit-diary-timer-mobile/assets/sugoroku/`](habit-diary-timer-mobile/assets/sugoroku/README.md)、設定ファイルは [`habit-diary-timer-mobile/src/features/sugoroku/images.ts`](habit-diary-timer-mobile/src/features/sugoroku/images.ts) です。配置済みのJPEG画像56枚を全55枠へ設定しています。スタートは `Map1.jpg` と `Map2.jpg` の2枚を、左右へのスワイプまたは前後の切り替えボタンで表示します。

各マスの画像は `images.ts` の `SUGOROKU_IMAGES` で設定します。例えば1マス目には次の設定で `No.1.jpg` を表示します。スタートの2枚と表示順は同じファイルの `SUGOROKU_START_IMAGES` で設定します。

```ts
"1": require("../../../assets/sugoroku/No.1.jpg"),
```

設定できるIDは `start`、`-6`〜`-1`、`1`〜`40`、`stop-1`〜`stop-4`、`goal-1`、`goal-2`、`retire`、`penalty` です。7・14・21・25の強制停止マスも番号のIDで設定します。`require()` のパスは文字列を直接記述し、実在するファイルだけを指定してください。ファイル名・拡張子は実際の画像に合わせて変更できます。画像未設定・読み込み失敗時は仮表示となります。

設定した画像は縦横比を維持して全体を表示し、タップすると全画面で拡大できます。スタートでは選択中のマップを拡大し、「閉じる」でゲーム画面へ戻っても選択を維持します。画像はアプリに同梱されるため、素材の変更後はアプリの再ビルド、WEB版は再エクスポートが必要です。現在の画像割り当てと差し替え手順は配置先のREADMEに記載しています。画像の内容を解析してルールを変える機能はありません。ルールは `src/features/sugoroku/game.ts` で管理します。

## オセロ

「部屋 → ゲーム部屋」のすごろくボタンの下から開きます。8×8の盤面で、あなたが白（先手）、二乃様が紫（後手）です。「二乃様の強さ」は「イージー」「ノーマル」「ハード」から対局前に選びます。イージーは合法手からランダムに選び、ノーマル・ハードは角や打てる場所の数、先の展開を評価します。ハードはノーマルより深く読みますが、処理量に上限を設けています。外部AIやネット接続は不要です。

「誘惑マス」は、ノーマルでは30手目以降（盤面の駒が34個以上）かつ二乃様の盤面評価が劣勢の場合、ハードでは開始時から、あなたの手番に表示します。単純な枚数差に加えて角や打てる場所なども評価します。イージーでは表示しません。二乃様側が有利になりそうな合法マスをピンクの印・座標・誘うセリフで示し、ほかの合法マスにも自由に打てます。ノーマルでは誘惑マス表示中、ハードでは対局開始・再開から終了まで `miminame.m4a` と `yuuwakubgm.m4a` を同時ループします。ハードではCPUの手番・パス・自動対局・履歴や確認画面の表示中も継続し、音声・BGM設定とそれぞれの音量を反映します。離席・バックグラウンド・対局終了時は専用音声を止めます。

ハードの通常CPUは、相手の合法手を1か所に制限する局面や、相手がパスする局面を重視して探索します。終盤の勝敗を優先し、勝てる展開の中では紫の石を多く残す手を狙います。全マスを紫にできるかは盤面と相手の手に依存し、合法手がなくなれば空きマスがあっても通常ルールで終了します。ハードの後半（30手目以降・盤面の石が34個以上）で、あなたの合法手が1か所になったときと、あなたがパスしてCPUが続けて打つときには、専用セリフを約2秒表示してから着手を再開します。前半は専用セリフによる待機を挟みません。自動対局中もこの間は進めず、履歴・確認画面・背景中は待機を中断し、戻ってから表示時間を取り直します。

対局中は石の数・手番・直前の着手を表示します。打てる場所がない手番は自動でパスし、両者が打てなくなると石の数で勝敗を判定します。誘惑マスの表示中には「降参する」ボタンを表示し、押すと次の操作を選ぶメニューが開きます。

- 手動配置の操作：セリフを表示し、その手だけ誘惑マスへの着手に絞ります。メニューを開いた時のマスを固定し、本人のタップを待ちます。
- 1手お任せの操作：セリフを1.2秒間表示してから、同じ誘惑マスに1手だけ自動で置きます。その後は通常の対局に戻ります。
- 高速自動対局の操作：最初にセリフを表示し、通常の待機500msの半分となる250ms間隔で双方を自動操作します。どちらの手番も二乃様に有利な合法手を探索し、終局まで進めます。勝敗は実際の枚数で判定します。「自動対局を一時停止／再開」で操作でき、履歴・確認画面・離席・バックグラウンド中も停止します。
- 「対局を終了して降参」：確認後、その場で敗北として記録します。

終了時は勝利・敗北・引き分けに応じたセリフを表示し、白を左上、紫を右下へ整列します。集計と実際の盤面は保持し、「対局終了時の盤面を見る」で切り替えられます。

対局開始・各着手・操作モードの変更時に、盤面・手番・強さ・開始日時を自動保存します。次回は「続きから」で再開でき、手動配置で固定したマスも保持します。高速自動対局は復元時に一時停止し、「自動対局を再開」を押して進めます。新しい対局に切り替える場合は、確認後に途中データを削除して強さを選び直します。保存失敗時は対局を止めて再試行を表示します。

終了・降参した対局は自動保存し、「プレイ履歴を表示する」から日付・勝敗・強さ・枚数・終了理由を最新100件まで確認できます。終了結果と途中データの消去は一度に保存し、終了済み対局の途中保存による復活を防ぎます。保存失敗時は同じ結果を再試行でき、保存完了前の再対局を防ぎます。保存キーは `nino-room:othello:v1`。途中対局・履歴・称号はバックアップ・復元に含まれ、全データ初期化または「調教日記・各部屋の記録」の部分初期化で消去します。ポイント連携はありません。

画面を離れたりアプリが背景に移るとCPUの待機処理を止め、画面が残っていれば復帰後に現在の手番から再開します。ルールとCPUは `src/features/othello/game.ts`、保存は同じフォルダーの `storage.ts`、画面は `app/(tabs)/othello.tsx` にあります。

## ゲームの称号

ゲーム成績はコレクション部屋の既存「称号」に追加します。オセロの初対局終了で「盤上の挑戦者」、初勝利で「オセロ初勝利」、ノーマル勝利で「ノーマル攻略」、ハード勝利で「ハード攻略」を獲得します。すごろくのゴール①の完了で「すごろく通常制覇」、ゴール②の完了で「すごろくハード制覇」を獲得します。ゴールに到着しただけでは獲得せず、完了操作で記録します。

称号の達成フラグは各ゲームのセーブデータに結果と同時に保存し、最新100件の履歴から結果が外れても残ります。旧形式の保存済み履歴からも達成を読み取り、既存の部屋・館の外の称号と並べて表示します。

## ゴミ汁廃棄履歴

検索欄では内容・日付・回数を全期間から検索でき、複数の単語はすべてを含む記録を表示します。内容が空欄でも日付や回数から検索できます。検索結果は日付付きの新しい順で表示し、「この日を表示」でその月・日へ移動、「検索をクリア」で元のカレンダー表示へ戻ります。日記・廃棄履歴とも検索中は日付単位の一括削除を表示せず、各結果の編集・個別削除を利用します。

タスク画面の下部、または記録・交換メニューの「お貢ぎ履歴」のすぐ上から開きます。入口は「お貢ぎ履歴」と同じ黒背景・赤文字です。調教日記と同じ月単位のカレンダーで日付を選び、廃棄回数と任意の内容を登録できます。日付の下には、その日に登録した回数の合計を表示します。同じ日に複数件を登録でき、個別の編集・削除に合わせて合計も更新します。内容は空欄でも保存でき、入力した文章は言語設定で変換せずに表示します。

保存は `src/services/disposalHistoryService.ts` で管理し、保存キーは `nino-room:disposal-history:v1` です。通常のバックアップ・復元に含まれ、全データ初期化または「調教日記・各部屋の記録」の部分初期化で消去します。

## 貞操帯管理記録

記録・交換メニューまたはタスク画面の下部から開きます。入口のボタンは調教部屋と同じ紫背景・白枠・白文字です。廃棄履歴と同じ月単位のカレンダーで、日付を選び「ロック済」「夢精」「射精」「洗浄」をプルダウンから選択し、任意の内容とともに記録します。同じ日に複数件を追加でき、個別に編集・削除できます。日付の下には、その日に記録した状態のアイコン（🔒・💦・×・🚿）を表示します。

射精を示す「×」は赤文字・太字で表示します。選択中の日付では白い背景を付け、赤いマスの上でも見分けられるようにします。

画像は日付ごとに1枚を共有し、追加・差し替え・削除できます。記録を1件削除しても、その日の共有画像は残ります。カレンダーはアイコン表示／画像表示を切り替えられ、画像がない日はアイコンを表示します。表示設定も保存します。内容は入力した原文のまま表示します。

記録は `src/services/chastityHistoryService.ts` の `nino-room:chastity-history:v1` に保存します。画像はAPPでは `private-room-files/chastity`、Web・Windowsでは既存のIndexedDBへ保存し、調教用・お仕置き用の再生候補には入りません。画像も移す場合は完全バックアップを利用してください。セーブデータのみを復元して画像が存在しない場合はアイコンを表示します。記録の部分初期化では添付画像も消去し、格納ファイルのみの初期化では状態・内容の記録を残します。

## 命令追加

管理・設定メニューの「ファイル格納」の直上にある「命令追加」から、「本日の命令」「射精管理部屋の貞操帯あり」「射精管理部屋の貞操帯なし」に自分の命令を追加・編集・削除できます。入口のボタンはファイル格納と同じ緑背景・白枠・白文字です。追加した文章は言語設定による翻訳や名前の置換を行わず、入力した原文のまま表示します。画面下のボタンで管理・設定メニューへ戻ります。

元からある命令は変更できず、実際に表示されたものだけ閲覧できます。管理期間を開始したときに内部で割り当てられた未来の命令は、それだけでは閲覧可能になりません。旧データでは完了済みの命令を閲覧済みとして引き継ぎます。

追加命令は次回の抽選から候補に入ります。射精管理では通常日の候補に加え、最終日の既存ルールは維持します。すでに引いた本日の命令や作成済みの管理期間の指示は、追加命令の編集・削除によって変わりません。追加命令と閲覧履歴はバックアップの対象です。記録の部分初期化では閲覧履歴を消去して追加命令を残し、全データ初期化では追加命令も消去します。

## お貢ぎ履歴

追加収入・お貢ぎの登録画面では、各日付ボタンの下にその日の登録済み合計金額を表示します。同日の複数登録は合算し、未登録の日は0円を表示します。金額は追加収入が緑、お貢ぎが赤で、選択日は赤背景・白文字で表示します。追加収入とお貢ぎ（雑費を含む）は別々に集計し、保存・削除・対象月の変更に合わせて更新します。

## データ保存

アプリはローカル完結です。

- SQLite DB: `habit_diary_timer.db`
- 設定: AsyncStorage
- 格納ファイル: アプリ専用領域の `private-room-files/training` と `private-room-files/punishment`。貞操帯管理の添付画像は `private-room-files/chastity`
- サーバー同期: なし
- アカウント認証: なし
- 端末変更時の自動移行: なし
- アプリ削除時: OSの仕様によりアプリ内データも削除

開始画面と管理・設定メニューの「アプリ設定」は共通で、どちらの入口からもサウンド・言語の変更、バックアップ・復元、一部／全データ初期化を利用できます。サウンド設定、言語設定、バックアップ・復元の順に表示します。命令追加は管理・設定メニューに独立した入口があります。バックアップはセーブデータのみ、または格納ファイルを含む完全バックアップを選べます。復元時は現在のデータを上書きし、セーブデータのみの復元では格納ファイルを変更しません。

完全バックアップはZIP形式で保存します。格納した画像・動画・音声は小分けに読み書きするため、大きな動画を一括で文字列に変換する必要がありません。セーブデータのみのバックアップは従来どおりJSON形式です。ファイル選択・書き出し・復元中は「処理中...」を表示し、バックアップ操作や初期化の重複実行を防ぎます。復元確認をキャンセルした場合は、一時的に展開したファイルを削除します。

新形式は非圧縮のZIP32で、全体4 GiB未満・格納ファイル9,999件まで対応します。セーブデータ部分の上限は8 MiBです。Android・iOSでは媒体を最大256 KiBずつ読み書きします。復元時は全ファイルの整合性を検証し、一時領域へ準備してから現在のデータを入れ替えます。

Web・Windows版の格納ファイルはIndexedDBへBlobとして保存します。APPの完全バックアップを復元するときも画像・動画をBase64の文字列に変換せず、ZIP内のバイナリから保存します。旧版のlocalStorageにある格納ファイルは、ファイル一覧やバックアップなどの初回利用時に自動移行し、保存の完了後に旧コピーを削除します。復元後の設定・データベース更新に失敗した場合は、元の格納ファイルへ戻します。保存容量はブラウザ・端末の空き容量に依存し、復元中は現在のファイルと復元するファイルの両方を置く空き容量が必要です。

旧形式のJSONバックアップも復元できます。ただしAndroid・iOSでは、メモリ不足を防ぐため16 MiBを超える旧形式のJSONファイルは読み込みません。画像・動画を含む大きな旧バックアップがある場合は、元の端末で更新版アプリから新しい完全バックアップ（ZIP）を作成してください。

「前回のバックアップ日時」は、この端末で書き出し操作を行った日時と種類の履歴です。保存先にファイルが存在することを確認した日時ではありません。書き出し後の案内に従って、保存先にバックアップファイルがあることを確認してください。

## APKビルド・配布

`stg` または `production` ブランチへのpushで `.github/workflows/build-android-apk.yml` が実行されます。

| ブランチ | 環境 | APK名 | 備考 |
|---|---|---|---|
| `main` | 開発 | なし | 自動ビルドなし |
| `stg` | STG | `nino-stg.apk` | 99,999ptのテストボーナスあり |
| `production` | PRD | `nino-prd.apk` | 本番配布用 |

処理内容:

1. Node.js 22 / Java 17 / Android SDKを準備
2. `npm ci --legacy-peer-deps`
3. TypeScriptとESLintを検証
4. Expo PrebuildでAndroidプロジェクトを生成
5. JavaScript bundle同梱のRelease APKを作成
6. GitHub Artifactへ保存
7. rcloneでGoogle DriveのSTG／PRDフォルダへ上書き保存

Google DriveアップロードにはRepository secret `GDRIVE_RCLONE_CONFIG_BASE64` が必要です。

## インストール時の注意

- APKはAndroid専用です。
- Google Play外から入れる場合、ブラウザまたはファイル管理アプリに「不明なアプリのインストール」許可が必要です。
- 旧APKから上書き更新するには、同じパッケージIDと署名鍵でビルドされている必要があります。
- 署名が異なるAPKは上書きできないため、旧版をアンインストールする必要があります。その場合、ローカルデータは失われます。
- Release APKはMetro接続不要です。`Unable to load script` が出るAPKはJavaScript bundleが同梱されていない不正なビルドです。

## トラブルシュート

| 症状 | 対応 |
|---|---|
| 起動エラー | 画面上の詳細エラーを確認し、再起動。必要なら設定から初期化 |
| Expo Goで接続できない | `npx expo start -c`。改善しなければ `npm run tunnel` |
| APKをインストールできない | Android 7以上、空き容量、不明なアプリの許可、署名不一致を確認 |
| 動画が表示されない | MP4を使用し、端末がコーデックを再生できるか確認 |
| 音が小さい | 効果音音量と端末メディア音量を確認。元音源の音量差にも注意 |
| ファイルを保存できない | Androidでは写真・動画へのアクセス許可と端末空き容量を確認。WEB／Windowsではダウンロード保存先とブラウザのダウンロード許可を確認 |
| APKビルドがJava heap spaceで失敗 | WorkflowのGradleメモリ設定と同時worker数を確認 |
| Android SDK設定が `Failed to find package 'tools'` で失敗 | `setup-android` の `packages` に `platform-tools` を明示し、取得できない旧 `tools` パッケージを除外する |
| Google Driveアップロード失敗 | `GDRIVE_RCLONE_CONFIG_BASE64` とrclone remote名 `gdrive` を確認 |

# 品質チェック

バージョン更新とリモートへのプッシュは、それぞれユーザーから明示的な指示がある場合にのみ行います。不具合修正や機能追加の依頼だけでは、自動でバージョンを変更したりプッシュしたりしません。

バージョン更新を指示された場合は、指定された対象・番号に合わせて、モバイルの `app.json`、対象アプリの `package.json`・`package-lock.json`、このREADMEの表を更新します。モバイルの更新ではAndroidの `versionCode` とiOSの `buildNumber` も前回より増やします。バックアップ内のアプリバージョンとWindowsの配布ファイル名は設定から取得します。

モバイル版では `npm run typecheck`、`npm run lint`、`npm test` を変更前後に実行します。
Windows版では `npm run typecheck` と `npm run lint` を実行します。Windows版の開発依存は再現可能なビルドのため固定しています。

共通の文言・日付・契約ロジックはルートの `shared` パッケージが唯一の編集元です。モバイル側へのコピー処理は不要です。

Web版のローカルDBは、旧 `nino-room-web-db-v1` の単一JSONを初回読込時にテーブル別の `nino-room-web-db-v2:*` キーへ自動移行します。これにより、変更のないテーブルまで一つの巨大JSONとして保存する構造を避けています。

画像と動画は画面から静的に参照されたものだけがExpoの本番エクスポート対象になります。未使用の作業用画像は配布物へ含まれません。
