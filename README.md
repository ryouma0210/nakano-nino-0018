# Nino Room

会話形式で各部屋のイベントを進め、チェック、調教、お仕置き、射精管理、ポイント、ご褒美などを端末内へ記録するスマートフォン向けローカルアプリです。

アプリ本体は `habit-diary-timer-mobile/` にあります。

## 現在の構成

| 項目 | 内容 |
|---|---|
| アプリ名 | Nino Room |
| アプリバージョン（スマホ・WEB・Windows共通） | 1.2.1 |
| パッケージID | `jp.local.habitdiarytimer` |
| Framework | Expo SDK 57 / React Native 0.86 |
| Language | TypeScript |
| 画面向き | 縦画面固定 |
| データ保存 | SQLite、AsyncStorage、アプリ専用ファイル領域 |
| 通信 | 通常利用では不要 |
| Android配布 | Release APK |
| iOS配布 | EAS / TestFlight設定のみ。現時点では実機配布未検証 |

## 主な特徴

- 二ノとのタップ式会話
- 設定した名前を使った呼びかけ
- 契約成立後だけ表示される赤文字の専用会話
- 日付単位の敗北・準備チェック
- 本日の命令、射精管理、調教、お仕置きの自動記録
- 調教・お仕置き用に分けた画像／動画の端末内格納
- リズムゲージ、効果音、ループ音声
- ポイント獲得、ご褒美交換、コレクション
- 二ノ様の控室での画像／動画表示、着せ替え
- 館の外へ出る軽量RPG風ミニゲーム
- ゲーム部屋のすごろく：マスごとの移動ルール、途中再開、プレイ履歴
- マイページでの名前変更、ステータス設定、弱点診断
- 起動時ログインボーナス確認、本日の記録、週間報告、記録カレンダー
- タスク画面で所持Pt、本日の獲得Pt、今日の達成状況、実施済・未完了項目を確認し、対象画面へ移動
- 称号・実績
- オフライン動作
- 「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターで主要画面へ移動
- 格納ファイルの複数選択、保存進捗・成功件数・失敗ファイルの表示

各調教系の部屋には「部屋から出る」と「ホームへ戻る」を配置します。ゲーム部屋から廊下へ移動するボタンも「部屋から出る」と表示します。記録・交換系の画面には「記録・交換メニューへ戻る」、管理・設定系の画面には「管理・設定メニューへ戻る」を配置します。

開始後の画面には「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターを表示します。「タスク」で本日の状況を確認できます。「記録」は記録・交換メニュー、「設定」は管理・設定メニューへの入口です。開始画面、館の外、全画面モーダルには表示せず、スマートフォンでの文字入力中は隠します。

Windows・WEBの広い画面では、同じ8項目を左側のナビゲーションに表示します。会話・画像と操作欄を左右に配置し、タスクは2列表示になります。ウィンドウを狭くすると縦並びへ戻ります。「アプリ設定」の「画面表示」で全画面表示を切り替えられ、Windows版では表示倍率も変更できます。Windows版の全画面状態と表示倍率は次回起動時にも引き継ぎます。

WEB・Windows版の控え室は、画像・動画の全体がウィンドウ内に収まるように表示します。調教・お仕置きのリズムゲージは中央配置・最大幅430pxとし、大画面でもマーカーの移動距離が伸びすぎないようにしています。リズムの周期・効果音・タイマーは画面サイズで変更しません。

ゲーム部屋、管理・設定メニュー、命令追加、貞操帯管理記録、ゴミ汁廃棄履歴にも、タップして進める二ノの会話を表示します。各画面に通常コメント2件を用意し、契約成立後は赤文字の契約者向けコメント2件を追加します。名前付きコメントには設定した名前を使い、英語・韓国語・中国語にも対応します。広い画面では既存の部屋と同じく会話と操作欄を左右に配置します。台詞は `shared/messages.ts` の `roomMessages.games`、`managementMenu`、`customOrders`、`chastityHistory`、`disposalHistory` で編集できます。

## アプリ内マニュアル

マニュアルの検索欄は、カテゴリをまたいで見出し・概要・説明文の全文を検索します。空白区切りの複数キーワードはすべて一致する項目に絞り込み、選択中の言語の説明文でも検索できます。検索をクリアすると元のカテゴリへ戻ります。

管理・設定メニューの「外部リンク」のすぐ上にある、白背景・黒文字の「マニュアル」から開きます。基本操作、各部屋、ゲーム、ポイント獲得、記録・交換、管理・設定に分けて概要と使い方を表示します。項目をタップすると詳しい説明が開き、もう一度タップすると閉じます。説明は一度に1項目を開き、カテゴリを切り替えると閉じた状態に戻ります。

「ポイント獲得」では、「獲得場所」に本日のタスクと同じ順番で14項目の名前とPtだけを箇条書きにします。「1日の獲得ポイント」では、管理1期間分を含む日次条件をすべて達成した場合の合計を、連続ログイン1日目452Pt・2〜6日目461Pt・7日目以降501Ptの3行で表示します。獲得条件の詳しい説明は各部屋で確認します。

マニュアルの閲覧で記録や契約の状態は変わりません。画面下の「管理・設定メニューへ戻る」から元のメニューへ戻れます。画面は `app/(tabs)/manual.tsx`、説明文は `src/features/manual/content.ts`、翻訳は `src/i18n/en.json`・`ko.json`・`zh.json` で管理します。

## 記録の比較・検索と共通操作

「本日の記録」の活動日と「週間報告」の集計月は、カレンダーアイコンから選択するとすぐに反映されます。「本日の記録」は選択した活動日を前日と比較し、ログインボーナスの確認・受取は常に当日分です。「週間報告」は直近7日と前7日、選択した月と前月を5項目の棒グラフで比較します。今月の途中は前月の同日まで（前月に同日がなければ月末まで）、過去の月は月全体で比較し、各期間の日付を表示します。集計値や棒を押すと、その項目の集計に使った日記・管理実績・ポイント取引・タイマー履歴の内訳を開きます。

日記・廃棄履歴・貞操帯管理記録・お貢ぎ履歴には、画面ごとに保存される検索条件があります。日記はキーワード・期間・記録種別・タグ（すべて一致）、管理記録は期間・状態、収支履歴は期間・支出／追加収入で絞り込めます。開始日・終了日はカレンダーアイコンから選び、「指定なし」でそれぞれの制限を解除できます。タグのない履歴にタグ項目は追加せず、既存の内容検索と組み合わせます。レポートから日記を開いた場合は、指定された条件を優先します。

ファイル格納の用途・並び順・表示列数は次回起動時も引き継ぎます。一覧は画面付近の項目を描画するFlatListで表示し、サムネイルの解像度・元画像・動画は変更しません。ゲームの素材選択にはファイル名検索があります。

調教・お仕置きの結果は、保存前に実施日時・実施時間・判定を固定して保持します。失敗時は共通の「再保存」案内を表示し、同じ結果を再試行します。日記・ポイント・保存済み印は一つのトランザクションで保存するため、再試行で二重記録されません。未保存のまま画面を移動する場合は、結果を破棄して移動するか確認します。保持中の結果はメモリ上にあり、OSによる強制終了後の復元には対応しません。

館の外では地図右上のクエストアイコンから「デイリー」「ストーリー」「遊び方」を切り替えられます。アイコン経由で開いて閉じたときは探索位置を変更しません。従来の青いクリスタルからも同じクエストを確認できます。

ループ音声の再生中だけ、スマートフォンでは下部メニューの上、PCではメイン画面の下端に小型プレイヤーを表示します。全停止を直接操作でき、タップすると個別停止と5・15・30・60分の停止タイマーを設定できます。停止タイマーは時刻を基準にし、アプリ復帰時にも期限を確認します。端末の省電力でJavaScriptの処理が停止している間の正確な停止時刻はOSの動作に依存します。

検索条件のUIと保存処理、日付・年月のカレンダー選択と日付検証、検索文字の正規化、期間比較のグラフ、未保存結果の再試行・離脱確認、クエスト一覧、ループ音声の名称と操作状態は共通部品・共通処理に集約しています。

## タスクの本日の状況

対象項目の表示順は「ログインボーナス→敗北部屋→洗脳部屋→準備部屋→本日の命令→調教部屋（初回のみ）→射精管理部屋→お仕置き部屋（初回のみ）→館の外（デイリー）→館の外（スライム倒し）→館の外（サキュバス討伐）→すごろく→オセロ→勃起我慢」です。未契約・対象外・管理期間外の項目は同じ優先順のまま一覧の末尾へまとめます。実施済になっても表示順は変えません。

タスク画面では「本日の状況」の上に当日の年月日と曜日を表示し、その下に所持Pt、本日の獲得Pt、今日の達成数と項目一覧を表示します。「すべて／未完了」で一覧を切り替え、初期表示と画面へ戻ったときは「未完了」です。未完了表示では、その日の対象かつ未完了の項目だけを既存の順番で表示します。「すべて」では完了した項目も緑色の「実施済」で表示し、対象外の項目も薄い表示と「対象外」「未契約」「管理期間外」の状態を付けます。どちらの表示でも各項目から対象画面へ移動でき、所持Pt・本日の獲得Pt・達成数の集計は表示切替で変わりません。対象外の項目は達成数の分子・分母に含めません。常時の集計対象はログインボーナス、本日の命令、準備部屋、洗脳部屋、調教部屋、館の外のデイリー・スライム倒し・サキュバス討伐、すごろく、オセロ、勃起我慢です。館の外のデイリーは「デイリー X/30pt」で当日の3つの報酬の受取状況を表示し、すべて受け取ると実施済になります。スライム倒しは「スライム倒し X/100pt」で当日の獲得状況を表示し、100ptで実施済になります。押すと館の外へ移動でき、翌日は0pt表示に戻ります。すごろく・オセロ・勃起我慢の初回クリア報酬50ptと、サキュバス討伐の初回報酬100ptを独立した項目に表示します。ゲームごとに難易度・モード共通で1日1回だけ達成し、デイリーの30pt枠・スライムの100pt枠とは別に集計します。お仕置き部屋は当日最新の調教結果が目標時間未達の場合だけ集計対象となり、その結果の保存以降に正常終了すると達成になります。再び目標未達になれば未完了に戻り、最新の結果が目標達成なら対象外になります。新しい調教記録には判定タグを保存し、以前の記録は既知の難易度と実施秒数から判定します。判定できない記録は集計対象外になります。

敗北部屋は契約中だけ、管理の指示は今日が管理期間内の場合だけ集計対象になります。タスクの敗北部屋の項目は、未契約なら「未契約」と表示して契約部屋へ直接移動します。契約済みなら敗北部屋へ移動し、完了前は「未完了」、完了後は「実施済」と表示します。管理には開始日・終了日を含めた「現在の日数／総日数 日目」と今日の完了状態を表示し、その日の指示を完了した後も日数表示を残します。管理の最終日を完了して期間が終了しても、その日の達成数には残ります。館の外のストーリークエストはこの集計に含めません。

全タスクに「獲得済み/上限pt」を表示します。ログインの上限は当日の連続日数に応じて1・10・50pt、各部屋の上限は現在の配点です。射精管理ではモード・許可日時・ルーレット回数と併せて表示します。対象外の項目もポイント表示を残します。調教部屋とお仕置き部屋は「（初回のみ）」と表示し、日次報酬がそれぞれ25pt・1ptの1回限りであることを示します。

部屋の獲得済みポイントは実際の付与記録を表示し、タスクの完了状態からは推定しません。旧配点で5ptを受け取った調教は「5/25pt」、完了済みでも付与記録がなければ「0/上限pt」です。お仕置きで1pt受取後に新しい対象タスクが発生した場合は、未完了でも「1/1pt」を保持します。表示の変更による追加付与はありません。

本日の獲得Ptは当日のプラスのポイント取引だけを合計し、消費・吸収による減少やSTG固定加算は含めません。お仕置きの新しい途中終了記録は達成に含めません。以前の履歴は正常終了と途中終了を同じ完了区分で保存していたため、過去分は保存済みの区分に従います。

各項目は実施済でも押すと対象画面へ移動します。タスク画面へ戻った時、タスク画面を開いたままアプリが前面へ復帰した時、日付が変わった時に保存済みのデータを読み直します。状況表示だけで報酬を付与したり、日記や管理指示を作成したりはしません。

## 射精管理部屋

「貞操帯あり」「貞操帯なし」から選び、最初のサイコロの出目×3日で当初の管理期間を決めます。進行中の管理を終えるまでは、もう一方の方法を開始できません。画面上部には延長を反映した終了予定日時と、そこまでの残り時間を表示します。

管理中は毎日最低2回ルーレットを回します。当日を終了するまでは追加で回せます。候補は期間延長6種類（3分・5分・30分・1時間・5時間・24時間）と、管理方法に対応した課題5種類の計11個で、各候補を同じ確率で1つ抽選します。延長枠には「＋3分 延長」「＋1日 延長」など、課題枠には⑦〜⑪を表示します。抽選結果・進行ログの延長も「＋時間 延長」の形式で表示します。課題が当たると当日の未完了課題に追加し、延長が当たると管理の終了予定日時にその時間を加算します。日付をまたぐ延長は管理日数も延ばします。

前日からの持ち越しを含む課題をすべて完了し、最低2回の抽選を終えて「本日を終了」を押すと25ptを獲得できます。2回抽選しただけでは付与されません。以前の形式で作成された当日の基本課題を、別枠で追加完了する必要はありません。最終指示は、延長後の終了予定日時を過ぎ、その日の抽選・課題を完了してから表示します。抽選結果は先に保存し、表示途中で画面を離れても同じ結果を保持します。1日完了や課題完了の再操作では報酬を重複付与しません。

ルーレットの候補・結果・延長後の期限は `app_settings` の `management_roulette_v1` に保存します。セーブデータのみ・完全バックアップの両方に含み、復元前に形式を検証します。「調教日記・各部屋の記録」の部分初期化と全データ初期化ではルーレットの記録も消去します。

## 調教・お仕置き・勃起我慢の格納メディア

「調教用」「お仕置き用」「勃起我慢用」の3つの入口からファイルを格納できます。格納後は各ファイルの「用途を変更」を開き、3つの用途から1つ以上を選びます。1つの画像・動画を複数の部屋で使っても、ファイル本体は1個だけ保持し、使用容量は重複して加算しません。以前に別々に取り込んだ重複ファイルは自動削除せず、必要な用途を1個のファイルに設定してから既存の削除操作で整理できます。ファイルの削除は設定したすべての用途に反映します。

既存ファイルの物理保存先 `purpose` と `name` は維持し、用途メタデータ `usages` だけを更新します。以前のファイルは元の保存先を唯一の用途として解釈します。APP版はメディア保存ディレクトリ内の `.usages/`、WEB版はIndexedDBのメタデータに保存し、用途変更のために動画の再コピーやBlob URLの作り直しを行いません。`fileStorageService.list("training" | "punishment" | "endurance")` は用途で絞り込み、引数なしの一覧と容量集計では各本体を1回だけ返します。貞操帯管理記録の専用画像は用途変更と通常のファイル一覧から除外します。

完全バックアップにはファイル本体と用途メタデータを含み、復元時もまとめて切り替え・ロールバックします。セーブデータのみの復元では、この端末にあるファイルと用途を変更しません。ファイル初期化では用途メタデータも消去します。

ファイル格納画面では、用途とファイル名で絞り込み、追加が新しい順・古い順・名前順に並べ替えられます。新旧順は保存名に含まれる日時を使い、日時が不明なファイルは末尾へ並べます。複数選択と表示中の全選択から、確認後にまとめて削除できます。検索・用途の変更時には選択を解除し、削除できなかったファイルは残して結果を表示します。

「格納しました」「削除しました」の完了表示は5秒後に消えます。失敗したファイルの案内は再試行のために残します。拡大表示では、現在の絞り込み・並べ替え順に左右のスワイプ、または「前へ」「次へ」で移動できます。先頭・末尾では止まり、表示中の番号も確認できます。

| デフォルト動画 | 3回再生後、次の動画へ |

## すごろく

「進行ログを見る」から、出目と補正後の値、移動前後のマス、強制停止、マスのルールによる移動、効果の付与・解除を最新100件まで新しい順で確認できます。操作番号は100件を超えても継続します。ログは途中保存と終了履歴に含まれ、プレイ履歴の各ゲームからも開けます。旧セーブに含まれない過去の操作は補わず、更新後の次の操作から記録します。

「部屋 → ゲーム部屋 → すごろく」から遊べます。各マスのイベント表記と設定済みの画像を表示します。「命令完了」でそのマスの移動・効果を適用し、移動先にもイベントがあれば、完了後にサイコロを振れます。イベント完了後にマスのルールで移動した場合は、移動先のお知らせを約5秒間表示します。お知らせの表示中も操作できます。画像の下のカードに現在のマス名、残りマス数、コース名を1行にまとめ、強制停止マスでは同じ行に赤色で「強制ストップ」と表示します。その下の操作は左列に「命令完了」「リタイア」「失敗」、右列に「サイコロを振る」「タイマー」を配置します。サイコロのイラストは振っている間のポップアップだけに表示し、通常の画面には出目・補正後の出目・マスのルールを文字で表示します。ゴール達成時は残りマス数を表示しません。遊び方には指定された「■すごろくルール」「■あると便利道具」「■マスの色について」の3項目を、元の改行・番号・記号を保って表示します。

「遊び方を見る」の直上にある「マップを確認」から専用モーダルを開き、開始時と同じ `Map1.jpg`・`Map2.jpg` を確認できます。左右へのスワイプまたは前後のボタンで切り替え、「閉じる」でゲームへ戻ります。

「サイコロを振る」を押すとポップアップが開き、約0.9秒間、回転しながら跳ねる演出の後に補正前の出目を表示します。移動の補正がある場合は、その出目を一度保持してルール適用を知らせ、再びサイコロを動かしてから補正後の目を表示し、結果を保存します。保存後はポップアップを自動で閉じ、出目の結果だけを文字で残します。補正前の値も「元の出目」として残します。移動マス数の代わりに、次のロールへ適用する効果を「デバフ付与中」とともに「強制1マス移動」「出た目 −3」「出た目 −2」で表示します。1マス固定の効果がある場合は減算より優先し、そのルールだけを表示します。ペナルティのサイコロには移動の補正を表示しません。

| マス・条件 | 移動・効果 |
|---|---|
| 通常 | 出目の数だけ進む |
| 1・8・15 | 完了後に -6 へ移動 |
| 2・6・13・26 | 完了後にスタートへ移動 |
| 12 / 20 / 37 | 完了後に 9 / 16 / 29 へ移動 |
| 7・14・21・25 | 通過時も強制停止。余った出目は破棄 |

| 21 | 通常モードで命令完了後、「出た目−2」を解除し、25の分岐まで強制1マス移動に置き換える |
| 25 | 初回完了後、ゴール①か延長を選択。延長は取り消せず、再訪しても分岐しない |

| 40の先 | ゴール② |

マイナスゾーンと1マス固定効果は出目補正より優先します。延長中の「−3」と、-1で付く「−2」は加算せず、延長の「−3」を使います。持続する「−2」は保存・再開後も維持します。旧仕様ですでに0へ消費された効果は訪問履歴が残っていないため推測で復元せず、次の-1の命令完了で再付与します。短いコースの残りマス数は25まで、延長時は挿入されたストップとゴール②を含む残りの位置数で計算します。

「リタイア」は専用イベントの完了後、「失敗」は直接、ペナルティ用のサイコロへ進みます。退出時点の残りマス数を固定し、`残りマス数 × 出目 × 10` の計算結果を単位なしで記録します。ゴール・ペナルティの「結果を記録して終了」でプレイ履歴に保存します。終了結果とプレイ履歴は、達成時に緑色で「ゴール①をクリア」または「ゴール②をクリア」と表示し、残りマスとペナルティは表示しません。未達成時は「未達成」、敗北コース（通常モード／ハードモード）、敗北マス、残りマス、ペナルティをこの順番で赤色表示します。敗北マスはリタイア・失敗を選んだ時点のマス名で、既存の保存済み位置から取得するため過去の履歴にも表示します。

進行は操作ごとに自動保存し、画面を離れたりアプリを再起動したりしても再開できます。終了履歴は各行の先頭に終了日（年月日）を表示し、最新100件を保持します。「プレイ履歴を表示する」ボタンから専用モーダルで新しい順に確認できます。通常画面には履歴の一覧を表示せず、履歴がない場合はモーダル内にその旨を表示します。履歴の「閉じる」ボタンはスクロール領域の外に固定しています。保存キーは `nino-room:sugoroku:v1`。既存のバックアップ・復元対象に含まれ、全データ初期化または「各部屋の記録」の部分初期化で消去します。

各マスの命令文は `src/features/sugoroku/instructions.ts` で管理し、画像の下のマス情報と一緒に表示します。日本語・英語・韓国語・中国語の言語設定に対応しています。右列の「サイコロを振る」の直下に「タイマー」ボタンを配置し、押すと残り時間・分設定・開始・リセットを操作するポップアップが開きます。時間設定は1〜999分の整数だけで、秒の入力欄はありません。「開始」ボタンは実行中に「一時停止」、一時停止中に「再開」へ切り替わります。開始後はボタンに「タイマー 00:00」の形式で残り時間を表示し、一時停止中もその時間を保ちます。開始前・リセット後・終了後はボタンの時間を表示しません。ポップアップを閉じても計測は続き、残り時間が0になると通知します。別の画面へ移動すると停止し、画面を開き直すと初期値に戻ります。アプリが背景にある間は経過時間を数え、復帰時に表示と通知を更新します。タイマーはアプリ再起動後には引き継ぎません。

「遊び方を見る」はゲーム開始前も閉じた状態です。開くと先頭にマップ①が通常モード、マップ②がハードモードであることと、ハードモードは25マスに到達した人だけが選択できる説明を表示します。

### 各マスへの画像の設定

画像の配置先は [`habit-diary-timer-mobile/assets/sugoroku/`](habit-diary-timer-mobile/assets/sugoroku/README.md)、設定ファイルは [`habit-diary-timer-mobile/src/features/sugoroku/images.ts`](habit-diary-timer-mobile/src/features/sugoroku/images.ts) です。配置済みのJPEG画像56枚を全55枠へ設定しています。スタートは `Map1.jpg` と `Map2.jpg` の2枚を、左右へのスワイプまたは前後の切り替えボタンで表示します。

各マスの画像は `images.ts` の `SUGOROKU_IMAGES` で設定します。例えば1マス目には次の設定で `No.1.jpg` を表示します。スタートの2枚と表示順は同じファイルの `SUGOROKU_START_IMAGES` で設定します。

```ts
"1": require("../../../assets/sugoroku/No.1.jpg"),
```

設定できるIDは `start`、`-6`〜`-1`、`1`〜`40`、`stop-1`〜`stop-4`、`goal-1`、`goal-2`、`retire`、`penalty` です。7・14・21・25の強制停止マスも番号のIDで設定します。`require()` のパスは文字列を直接記述し、実在するファイルだけを指定してください。ファイル名・拡張子は実際の画像に合わせて変更できます。画像未設定・読み込み失敗時は仮表示となります。

設定した画像は縦横比を維持して全体を表示し、タップすると全画面で拡大できます。スタートでは選択中のマップを拡大し、「閉じる」でゲーム画面へ戻っても選択を維持します。画像はアプリに同梱されるため、素材の変更後はアプリの再ビルド、WEB版は再エクスポートが必要です。現在の画像割り当てと差し替え手順は配置先のREADMEに記載しています。画像の内容を解析してルールを変える機能はありません。ルールは `src/features/sugoroku/game.ts` で管理します。

## オセロ

対局開始後は「ゲーム部屋へ戻る」の上に「開始前画面へ戻る」を表示します。進行中は確認後に盤面と手番を保存し、強さ選択と「続きから」の画面へ戻ります。高速自動対局は一時停止で保存します。保存に失敗した場合は盤面を保持し、再試行できます。対局終了後も同じボタンで開始前画面へ戻れます。

「部屋 → ゲーム部屋」のすごろくボタンの下から開きます。8×8の盤面で、あなたが白（先手）、二乃様が紫（後手）です。「二乃様の強さ」は「イージー」「ノーマル」「ハード」から対局前に選びます。イージーは合法手からランダムに選び、ノーマル・ハードは角や打てる場所の数、先の展開を評価します。ハードはノーマルより深く読みますが、処理量に上限を設けています。外部AIやネット接続は不要です。

「誘惑マス」は、ノーマルでは30手目以降（盤面の駒が34個以上）かつ二乃様の盤面評価が劣勢の場合、ハードでは開始時から、あなたの手番に表示します。単純な枚数差に加えて角や打てる場所なども評価します。イージーでは表示しません。二乃様側が有利になりそうな合法マスをピンクの印・座標・誘うセリフで示し、ほかの合法マスにも自由に打てます。ノーマルでは誘惑マス表示中、ハードでは対局開始・再開から終了まで `miminame.m4a` と `yuuwakubgm.m4a` を同時ループします。ハードではCPUの手番・パス・自動対局・履歴や確認画面の表示中も継続し、音声・BGM設定とそれぞれの音量を反映します。離席・バックグラウンド・対局終了時は専用音声を止めます。

ハードの通常CPUは、相手の合法手を1か所に制限する局面や、相手がパスする局面を重視して探索します。終盤の勝敗を優先し、勝てる展開の中では紫の石を多く残す手を狙います。同じ局面の読みを再利用し、残り24マス以下では最大6手、14マス以下では終局までの読みを目指します。探索は150ms・12,000局面以内に制限し、最後まで読めた深さの結果を採用します。高速自動対局も単なる点差ではなく紫の最終枚数を優先します。全マスを紫にできるかは盤面と相手の手に依存し、合法手がなくなれば空きマスがあっても通常ルールで終了します。

通常対局では、CPUが角を取る手、または5枚以上を返す手を選んだときに、セリフを約5秒表示してから打ちます。石は約520msかけて縮んでから反対の色へ返り、反転が終わるまで次の着手を受け付けません。ハードの後半（30手目以降・盤面の石が34個以上）で、あなたの合法手が1か所になったときと、あなたがパスしてCPUが続けて打つときには、専用セリフを約5秒表示してから着手を再開します。前半はこの専用セリフによる待機を挟みません。履歴・確認画面・背景中は演出を中断し、復帰後に反転の残りを再開します。

対局中は石の数・手番・直前の着手を表示します。打てる場所がない手番は自動でパスし、両者が打てなくなると石の数で勝敗を判定します。誘惑マスの表示中には「降参する」ボタンを表示し、押すと次の操作を選ぶメニューが開きます。

- 手動配置の操作：セリフを表示し、その手だけ誘惑マスへの着手に絞ります。メニューを開いた時のマスを固定し、本人のタップを待ちます。
- 1手お任せの操作：セリフを5秒間表示してから、同じ誘惑マスに1手だけ自動で置きます。その後は通常の対局に戻ります。
- 高速自動対局の操作：5倍速で、セリフによる待機を挟まず、着手前の待機は100ms、石の反転は104msにして双方を自動操作します。どちらの手番も二乃様に有利な合法手を探索し、終局まで進めます。実行中は誘惑・角取り・大量反転・追い詰めたときのコメントを表示せず、手番・枚数・一時停止の操作を残します。高速自動で終了した対局では、二乃様が勝ったときだけ終了セリフを表示します。勝敗は実際の枚数で判定します。「自動対局を一時停止／再開」で操作でき、履歴・確認画面・離席・バックグラウンド中も停止します。最後の反転が終わってから石を整列します。
- 「対局を終了して降参」：確認後、その場で敗北として記録します。

通常対局の終了時は勝利・敗北・引き分けに応じたセリフを表示し、白を左上、紫を右下へ整列します。高速自動対局でも二乃様の勝利時はセリフを残し、それ以外は整列だけを行います。集計と実際の盤面は保持し、「対局終了時の盤面を見る」で切り替えられます。

対局開始・各着手・操作モードの変更時に、盤面・手番・強さ・開始日時を自動保存します。次回は「続きから」で再開でき、手動配置で固定したマスも保持します。高速自動対局は復元時に一時停止し、「自動対局を再開」を押して進めます。新しい対局に切り替える場合は、確認後に途中データを削除して強さを選び直します。保存失敗時は対局を止めて再試行を表示します。

終了・降参した対局は自動保存し、「プレイ履歴を表示する」から日付・勝敗・強さ・枚数・終了理由を最新100件まで確認できます。終了結果と途中データの消去は一度に保存し、終了済み対局の途中保存による復活を防ぎます。保存失敗時は同じ結果を再試行でき、保存完了前の再対局を防ぎます。保存キーは `nino-room:othello:v1`。途中対局・履歴・称号はバックアップ・復元に含まれ、全データ初期化または「調教日記・各部屋の記録」の部分初期化で消去します。本日初回の勝利で50ptを獲得します。強さに関係なく1日1回で、引き分け・敗北・降参は対象外です。報酬を獲得した結果と履歴に「本日初回クリア報酬：＋50Pt」を表示します。

画面を離れたりアプリが背景に移るとCPUの待機処理を止め、画面が残っていれば復帰後に現在の手番から再開します。ルールとCPUは `src/features/othello/game.ts`、保存は同じフォルダーの `storage.ts`、画面は `app/(tabs)/othello.tsx` にあります。

## 勃起我慢

ゲーム開始後は「ゲーム部屋へ戻る」の上に「開始前画面へ戻る」を表示します。現在の進行とタイマー・動画位置を保存して開始前画面へ戻り、「続きから」で再開できます。保存に失敗した場合はプレイ画面を保持します。

ゲーム中の「前へ／次へ」とスライド操作では、クリア済みの画像と現在の画像を閲覧できます。未クリアの先の画像は、そのスライドの条件を達成するまで開けません。見返している間は現在のタイマーを一時停止し、「現在の画像へ戻る」で進行中の画像へ戻れます。最後までクリアした後は全画像を閲覧でき、「完了」を押した時点で履歴を保存してゲームを終了します。「完了」が表示される状態では、1分タイマーと「我慢失敗」「リタイア」を非表示にします。

「ゲーム部屋 → 勃起我慢」から選びます。①〜⑤は各4枚の画像、⑥は動画1本、任意のゲームは「ファイル格納」で勃起我慢用に指定した画像・動画から最大100個を選びます。「ファイル選択」は別画面のモーダルで、サムネイルとファイル名を確認してチェックを切り替え、「選択完了」で戻ります。初回は対象の画像・動画を先頭100件まで選択済みにします。同じ画面を維持したまま選択を開き直したり、別画面から戻ったりしても選択を保持し、画面を新しく開いた場合は初期選択に戻ります。再読み込み時は削除された対象を除き、新しい対象を上限まで選択に追加し、以前に外した対象は未選択のままにします。格納ファイルの参照は物理保存先と名前の組で行い、用途を追加してもファイルを複製しません。

①〜⑤と任意のゲームは、各スライドで1分タイマーを開始します。時間が終わると次へ進める状態になりますが、スライドは自動で切り替えず、自分で操作して次へ進みます。3分タイマーは「我慢失敗」の後だけ表示します。赤文字の「我慢失敗」を押した後は、準備ができたら自分で3分タイマーを開始し、同じスライドで3分を終えてから次へ進めます。白文字の「リタイア」はその時点のスライド・失敗回数・終了日時を履歴に保存して終了します。画面を離れたとき、アプリがバックグラウンドへ移ったとき、履歴・確認画面を開いたときはタイマーと動画を一時停止します。タイマーは「再開」を押すまで停止します。①〜⑤と任意のゲームでは、1分タイマー中は `miminame.m4a` と `bokkisiro.m4a`、失敗後の3分タイマー中は `miminame.m4a` と `ikuna-sine.m4a` を設定に従って同時再生します。開始・再開で音声を再生し、すべての対象タイマーの一時停止・時間終了、離席、バックグラウンド、履歴・確認画面、ゲーム終了で停止します。次スライドへ移った直後は、そのスライドのタイマーを開始するまで音声を再生しません。

⑥は動画を最後まで再生して「最後まで我慢できた」を押すか、「我慢失敗」「リタイア」でその時点で終了します。1分・3分タイマーは表示せず、動画の再生位置と全体の長さを表示します。一時停止・シークに合わせて表示を更新し、終了時の再生位置をミリ秒で保存、画面では分:秒で表示します。動画の拡大・縮小でも同じ再生位置を維持します。以前の履歴に再生位置がない場合は「記録なし」と表示します。

⑥の同梱動画の音声は、耳舐め音声に合わせて平均−16.84 LUFSへ調整済みです。AAC出力後の実測は−16.84 LUFS、真のピークは−0.99 dBTPです。映像は再圧縮せず、映像データ・フレーム数・再生時間を維持しています。

任意のゲームの動画は、タイマー開始前・一時停止中・時間終了後もループ再生します。動画自体の音声はタイマーの動作中だけ再生し、それ以外は映像のみ表示します。タイマーの終了だけではスライドを送りません。動画は離席・バックグラウンド・履歴や確認画面・ゲーム終了で停止します。⑥の動画はループせず、最後までの再生を完了条件に使います。

## 貞操帯管理記録

記録・交換メニューまたはタスク画面の下部から開きます。入口のボタンは調教部屋と同じ紫背景・白枠・白文字です。廃棄履歴と同じ月単位のカレンダーで、日付を選び「ロック済」「夢精」「射精」「洗浄」をプルダウンから選択し、任意の内容とともに記録します。内容欄には、選択した状態に合った入力例を表示します。同じ日に複数件を追加でき、個別に編集・削除できます。日付の下には、その日に記録した状態のアイコン（🔒・💦・×・🚿）を表示します。

状態アイコンは登録順によらず、ロック済（🔒）、夢精（💦）、射精（×）、洗浄（🚿）の順に表示します。射精を示す「×」は赤文字・太字で、専用の背景は付けません。画面内の操作ボタンは白背景・黒文字とし、「タスクへ戻る」は共通の水色背景・白文字です。

画像は日付ごとに1枚を共有し、追加・差し替え・削除できます。記録を1件削除しても、その日の共有画像は残ります。カレンダーはアイコン表示／画像表示を切り替えられ、画像がない日はアイコンを表示します。表示設定も保存します。内容は入力した原文のまま表示します。

「この日の画像」の下には、日付ごとの限界度合いのプルダウンと、ご主人様への思いの入力欄を表示します。限界度合いは10刻み（10〜90）、MAX♡（保存値100）、「限界です。助けてください♡」から選びます。「限界です。助けてください♡」はMAX♡と区別できる状態も保存します。以前に保存した1〜100の値は選び直すまで保持します。「この日の入力を保存」で保存・更新します。どちらも任意で、限界度合いを「未選択」にし、思いを空欄にして保存すると、その日のこの2項目だけを消去します。状態の記録や画像は残ります。編集中にカレンダーの日付を切り替えても、その画面内では日付ごとの下書きを保持します。保存した文章は自動翻訳しません。この2項目も記録と同じ保存データに含み、セーブデータのみ・完全バックアップの両方で引き継ぎます。

記録は `src/services/chastityHistoryService.ts` の `nino-room:chastity-history:v1` に保存します。画像はAPPでは `private-room-files/chastity`、Web・Windowsでは既存のIndexedDBへ保存し、調教用・お仕置き用の再生候補には入りません。画像も移す場合は完全バックアップを利用してください。セーブデータのみを復元して画像が存在しない場合はアイコンを表示します。記録の部分初期化では添付画像も消去し、格納ファイルのみの初期化では状態・内容の記録を残します。

## 命令追加

管理・設定メニューの「ファイル格納」の直上にある「命令追加」から、「本日の命令」「射精管理部屋の貞操帯あり」「射精管理部屋の貞操帯なし」に自分の命令を追加・編集・削除できます。入口のボタンはファイル格納と同じ緑背景・白枠・白文字です。追加した文章は言語設定による翻訳や名前の置換を行わず、入力した原文のまま表示します。画面下のボタンで管理・設定メニューへ戻ります。

元からある命令は変更できず、実際に表示されたものだけ閲覧できます。管理期間を開始したときに内部で割り当てられた未来の命令は、それだけでは閲覧可能になりません。旧データでは完了済みの命令を閲覧済みとして引き継ぎます。

追加命令は次回の抽選から候補に入ります。射精管理では通常日の候補に加え、最終日の既存ルールは維持します。すでに引いた本日の命令や作成済みの管理期間の指示は、追加命令の編集・削除によって変わりません。追加命令と閲覧履歴はバックアップの対象です。記録の部分初期化では閲覧履歴を消去して追加命令を残し、全データ初期化では追加命令も消去します。

## データ保存

アプリはローカル完結です。

- SQLite DB: `habit_diary_timer.db`
- 設定: AsyncStorage
- 格納ファイル: アプリ専用領域の `private-room-files/training` と `private-room-files/punishment`。貞操帯管理の添付画像は `private-room-files/chastity`
- サーバー同期: なし
- アカウント認証: なし
- 端末変更時の自動移行: なし
- アプリ削除時: OSの仕様によりアプリ内データも削除

開始画面と管理・設定メニューの「アプリ設定」は共通で、どちらの入口からもサウンド・言語の変更、バックアップ・復元、一部／全データ初期化を利用できます。サウンド設定、言語設定、バックアップ・復元の順に表示します。命令追加は管理・設定メニューに独立した入口があります。バックアップはセーブデータのみ、または格納ファイルを含む完全バックアップを選べます。復元時は現在のデータを上書きし、セーブデータのみの復元では格納ファイルを変更しません。

完全バックアップはZIP形式で保存します。格納した画像・動画・音声は小分けに読み書きするため、大きな動画を一括で文字列に変換する必要がありません。セーブデータのみのバックアップは従来どおりJSON形式です。ファイル選択・書き出し・復元中は「処理中...」を表示し、バックアップ操作や初期化の重複実行を防ぎます。復元確認をキャンセルした場合は、一時的に展開したファイルを削除します。

新形式は非圧縮のZIP32で、全体4 GiB未満・格納ファイル9,999件まで対応します。セーブデータ部分の上限は8 MiBです。Android・iOSでは媒体を最大256 KiBずつ読み書きします。復元時は全ファイルの整合性を検証し、一時領域へ準備してから現在のデータを入れ替えます。

Web・Windows版の格納ファイルはIndexedDBへBlobとして保存します。APPの完全バックアップを復元するときも画像・動画をBase64の文字列に変換せず、ZIP内のバイナリから保存します。旧版のlocalStorageにある格納ファイルは、ファイル一覧やバックアップなどの初回利用時に自動移行し、保存の完了後に旧コピーを削除します。復元後の設定・データベース更新に失敗した場合は、元の格納ファイルへ戻します。保存容量はブラウザ・端末の空き容量に依存し、復元中は現在のファイルと復元するファイルの両方を置く空き容量が必要です。

旧形式のJSONバックアップも復元できます。ただしAndroid・iOSでは、メモリ不足を防ぐため16 MiBを超える旧形式のJSONファイルは読み込みません。画像・動画を含む大きな旧バックアップがある場合は、元の端末で更新版アプリから新しい完全バックアップ（ZIP）を作成してください。

「前回のバックアップ日時」は、この端末で書き出し操作を行った日時と種類の履歴です。保存先にファイルが存在することを確認した日時ではありません。書き出し後の案内に従って、保存先にバックアップファイルがあることを確認してください。

- APKはAndroid専用です。
- Google Play外から入れる場合、ブラウザまたはファイル管理アプリに「不明なアプリのインストール」許可が必要です。

# 品質チェック

バージョン更新とリモートへのプッシュは、それぞれユーザーから明示的な指示がある場合にのみ行います。不具合修正や機能追加の依頼だけでは、自動でバージョンを変更したりプッシュしたりしません。

バージョン更新を指示された場合は、指定された対象・番号に合わせて、モバイルの `app.json`、対象アプリの `package.json`・`package-lock.json`、このREADMEの表を更新します。モバイルの更新ではAndroidの `versionCode` とiOSの `buildNumber` も前回より増やします。バックアップ内のアプリバージョンとWindowsの配布ファイル名は設定から取得します。

モバイル版では `npm run typecheck`、`npm run lint`、`npm test` を変更前後に実行します。
Windows版では `npm run typecheck` と `npm run lint` を実行します。Windows版の開発依存は再現可能なビルドのため固定しています。

共通の文言・日付・契約ロジックはルートの `shared` パッケージが唯一の編集元です。モバイル側へのコピー処理は不要です。

Web版のローカルDBは、旧 `nino-room-web-db-v1` の単一JSONを初回読込時にテーブル別の `nino-room-web-db-v2:*` キーへ自動移行します。これにより、変更のないテーブルまで一つの巨大JSONとして保存する構造を避けています。

画像と動画は画面から静的に参照されたものだけがExpoの本番エクスポート対象になります。未使用の作業用画像は配布物へ含まれません。
