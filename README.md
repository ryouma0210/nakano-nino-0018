# Nino Room

会話形式で各部屋のイベントを進め、チェック、調教、お仕置き、射精管理、ポイント、ご褒美などを端末内へ記録するスマートフォン向けローカルアプリです。

アプリ本体は `habit-diary-timer-mobile/` にあります。

## 現在の構成

| 項目 | 内容 |
|---|---|
| アプリ名 | Nino Room |
| アプリバージョン | 1.0.0 |
| パッケージID | `jp.local.habitdiarytimer` |
| Framework | Expo SDK 57 / React Native 0.86 |
| Language | TypeScript |
| 画面向き | 縦画面固定 |
| データ保存 | SQLite、AsyncStorage、アプリ専用ファイル領域 |
| 通信 | 通常利用では不要 |
| Android配布 | Release APK |
| iOS配布 | EAS / TestFlight設定のみ。現時点では実機配布未検証 |

## 主な特徴

- 二ノとのタップ式会話
- 設定した名前を使った呼びかけ
- 契約成立後だけ表示される赤文字の専用会話
- 日付単位の敗北・準備チェック
- 本日の命令、射精管理、調教、お仕置きの自動記録
- 調教・お仕置き用に分けた画像／動画の端末内格納
- リズムゲージ、効果音、ループ音声
- ポイント獲得、ご褒美交換、コレクション
- 二ノ様の控室での画像／動画表示、着せ替え
- 館の外へ出る軽量RPG風ミニゲーム
- マイページでの名前変更、ステータス設定、弱点診断
- 起動時ログインボーナス確認、本日の記録、週間報告、記録カレンダー
- タスク画面で所持Pt、本日の獲得Pt、今日の達成状況、実施済・未完了項目を確認し、対象画面へ移動
- 称号・実績
- オフライン動作
- 「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターで主要画面へ移動
- 格納ファイルの複数選択、保存進捗・成功件数・失敗ファイルの表示

各調教系の部屋には「廊下に戻る」と「ホームへ戻る」を配置します。記録・交換系の画面には「記録・交換メニューへ戻る」、管理・設定系の画面には「管理・設定メニューへ戻る」を配置します。

開始後の画面には「ホーム・タスク・部屋・控え室・館の外・記録・設定・マイページ」の固定フッターを表示します。「タスク」で本日の状況を確認できます。「記録」は記録・交換メニュー、「設定」は管理・設定メニューへの入口です。開始画面、館の外、全画面モーダルには表示せず、スマートフォンでの文字入力中は隠します。

## タスクの本日の状況

対象項目の表示順は「ログインボーナス→敗北部屋→洗脳部屋→準備部屋→本日の命令→調教部屋→射精管理部屋→お仕置き部屋→館の外」です。未契約・対象外・管理期間外の項目は同じ優先順のまま一覧の末尾へまとめます。実施済になっても表示順は変えません。

タスク画面に所持Pt、本日の獲得Pt、今日の達成数と全項目を表示します。完了した項目も一覧に残し、緑色の「実施済」で表示します。条件の対象外の項目は非表示にせず、薄い表示と「対象外」「未契約」「管理期間外」の状態を付け、押すと対象画面へ移動できます。対象外の項目は達成数の分子・分母に含めません。常時の集計対象はログインボーナス、本日の命令、準備部屋、洗脳部屋、調教部屋、館の外です。館の外は「スライム倒し X/100pt」で当日の獲得状況を表示し、100ptで実施済になります。押すと館の外へ移動でき、翌日は0pt表示に戻ります。お仕置き部屋は当日最新の調教結果が目標時間未達の場合だけ集計対象となり、その結果の保存以降に正常終了すると達成になります。再び目標未達になれば未完了に戻り、最新の結果が目標達成なら対象外になります。新しい調教記録には判定タグを保存し、以前の記録は既知の難易度と実施秒数から判定します。判定できない記録は集計対象外になります。

敗北部屋は契約中だけ、管理の指示は今日が管理期間内の場合だけ集計対象になります。タスクの敗北部屋の項目は、未契約なら「未契約」と表示して契約部屋へ直接移動します。契約済みなら敗北部屋へ移動し、完了前は「未完了」、完了後は「実施済」と表示します。管理には開始日・終了日を含めた「現在の日数／総日数 日目」と今日の完了状態を表示し、その日の指示を完了した後も日数表示を残します。管理の最終日を完了して期間が終了しても、その日の達成数には残ります。館の外のクエストはこの集計に含めません。

本日の獲得Ptは当日のプラスのポイント取引だけを合計し、消費・吸収による減少やSTG固定加算は含めません。お仕置きの新しい途中終了記録は達成に含めません。以前の履歴は正常終了と途中終了を同じ完了区分で保存していたため、過去分は保存済みの区分に従います。

各項目は実施済でも押すと対象画面へ移動します。タスク画面へ戻った時、タスク画面を開いたままアプリが前面へ復帰した時、日付が変わった時に保存済みのデータを読み直します。状況表示だけで報酬を付与したり、日記や管理指示を作成したりはしません。

## 二ノ様の控室

二ノ様の控室は、通常の部屋一覧とは別の専用画面です。スマートフォンのキャラクターゲームのように、画面中央へ二ノを大きく表示し、下部にセリフ、横に操作ボタンを配置します。

現在の機能:

- 画像／動画表示
- セリフ切り替え
- 横ボタンから画像／動画、衣装、戻るを操作
- 衣装変更
- 交換衣装の300pt交換

通常衣装では共通の控室メッセージと通常衣装メッセージを表示します。通常衣装以外では、選択中の衣装ごとのメッセージだけを表示します。

## 館の外へ

館の外へは、二ノ様の控室の下にある軽量RPG風ミニゲームです。
入室時と再表示時は必ず中央の十字路から開始し、上へ進んだ場合のみ誘惑の森を表示します。

現在の機能:

- ヘッダなしで、マップエリアを画面上部に大きく表示
- 下部に「自分のステータス」と「操作」を分けて表示
- 下部パネルはスマホのナビゲーションバーに被りにくいよう、コンパクトに表示
- 自分のステータスには、Lv、HP、MP、本日獲得pt、魅了状態を表示
- マップを移動した場合は、移動元に合わせて端から開始します（右から戻ったら右端、上から戻ったら上側など）
- 説明文や結果メッセージはマップ内の最下部に表示し、タップすると閉じます
- 下方向またはドア操作でホーム画面へ戻る
- 中央の十字路には設定ポイントがあり、触れるとモーダルで主人公Lv、サキュバスLv、魅了を調整できます
- サキュバスLvは主人公Lvとは別に保存され、設定ではLv.1〜100の範囲で調整できます
- 設定ポイントのクリスタルは、立ったまま横方向に回転しているように表示します
- 右の草原では背景に固定されたスライムではなく、4体のスライムがマップ上を自由に移動します
- 移動中のスライムへ主人公が接触すると討伐して消えます
- スライム討伐は1回10pt、1日100ptまで獲得できます
- 左の浄化エリアへ入ると、HP／MPを自動で全回復し、魅了も解除します。回復メッセージは緑色で表示します
- 上の誘惑の森では、影に隠れたサキュバスへ近づくと「！」が表示され、戦闘開始イベントへ移行します
- 戦闘画面は画像をメインに表示し、画像まわりの白枠は出さず、画像内の上にサキュバスLv／HPを表示します
- 画像上には「コメント」または「選択肢＋主人公HP／MP／魅了状態」のどちらかだけを表示し、コメントをタップすると選択肢へ切り替わります
- コメントは右下に「タップ ▼」を表示し、次に進める場所を分かりやすくしています
- 戦闘コマンドは「戦う」「降参する」「逃げる」の階層式です
- 「戦う」では「攻撃」「防御」を選択できます。防御すると誘惑ダメージを半減し、MPを少し回復します
- 「降参する」では「おっぱい」「お尻」「足裏」の負けイベントを選択できます
- 「逃げる」「攻撃」「防御／攻撃回避」には、それぞれ別の外RPG用効果音が鳴ります
- 魅了状態では逃げることができず、攻撃しても相手に当たりません。左の浄化エリアへ移動すると解除されます
- 攻撃するとサキュバスHPを削り、その後サキュバスが通常攻撃または誘惑攻撃で反撃します。通常攻撃時は尻尾イラストを表示します
- サキュバスの誘惑攻撃時は、耳舐め音声または乳首責め音声をランダムに再生します
- 耳舐め誘惑ではキスマーク画像を表示して魅了状態になり、乳首責め誘惑ではハート画像を表示します
- 誘惑攻撃ダメージは、初級10、中級20、女王50
- HPが0になる、または負けイベントを選ぶと、01画像で5セリフ、02画像で10セリフ、03画像で5セリフの誘惑イベントに入り、画像とコメントをタップ送りで切り替えます
- 誘惑イベント中は画像を大きく表示し、HP／MP／サキュバスHPバーは表示しません
- 負けイベント中は誘惑BGMへ切り替わり、02画像からループ音、03画像から射精音を再生します
- ゲームオーバー時は射精1回扱いで、主人公Lv、MP100、Pt50を吸収されます
- 主人公はLv.1／HP1／MP1になり、吸収されたLvはサキュバス側へ加算されます（最大Lv.100）
- ゲームオーバー時の結果には、吸収後のサキュバスLvも表示します
- バトル中は戦闘BGM、魅了状態では専用BGMへ切り替わります

## 調教・お仕置きメディア

調教用ファイルとお仕置き用ファイルは別フォルダで管理します。

「前回のバックアップ日時」は、この端末で書き出し操作を行った日時と種類の履歴です。保存先にファイルが存在することを確認した日時ではありません。書き出し後の案内に従って、保存先にバックアップファイルがあることを確認してください。

## APKビルド・配布

`stg` または `production` ブランチへのpushで `.github/workflows/build-android-apk.yml` が実行されます。

| ブランチ | 環境 | APK名 | 備考 |
|---|---|---|---|
| `main` | 開発 | なし | 自動ビルドなし |
| `stg` | STG | `nino-stg.apk` | 99,999ptのテストボーナスあり |
| `production` | PRD | `nino-prd.apk` | 本番配布用 |

処理内容:

1. Node.js 22 / Java 17 / Android SDKを準備
2. `npm ci --legacy-peer-deps`
3. TypeScriptとESLintを検証
4. Expo PrebuildでAndroidプロジェクトを生成
5. JavaScript bundle同梱のRelease APKを作成
6. GitHub Artifactへ保存
7. rcloneでGoogle DriveのSTG／PRDフォルダへ上書き保存

Google DriveアップロードにはRepository secret `GDRIVE_RCLONE_CONFIG_BASE64` が必要です。

## インストール時の注意

- APKはAndroid専用です。
- Google Play外から入れる場合、ブラウザまたはファイル管理アプリに「不明なアプリのインストール」許可が必要です。
- 旧APKから上書き更新するには、同じパッケージIDと署名鍵でビルドされている必要があります。
- 署名が異なるAPKは上書きできないため、旧版をアンインストールする必要があります。その場合、ローカルデータは失われます。
- Release APKはMetro接続不要です。`Unable to load script` が出るAPKはJavaScript bundleが同梱されていない不正なビルドです。

Windows版では `npm run typecheck` と `npm run lint` を実行します。Windows版の開発依存は再現可能なビルドのため固定しています。

共通の文言・日付・契約ロジックはルートの `shared` パッケージが唯一の編集元です。モバイル側へのコピー処理は不要です。

Web版のローカルDBは、旧 `nino-room-web-db-v1` の単一JSONを初回読込時にテーブル別の `nino-room-web-db-v2:*` キーへ自動移行します。これにより、変更のないテーブルまで一つの巨大JSONとして保存する構造を避けています。

画像と動画は画面から静的に参照されたものだけがExpoの本番エクスポート対象になります。未使用の作業用画像は配布物へ含まれません。
